# Curio — Source Directory

Verified, publicly accessible sources for each topic. Everything here was
checked via live search rather than pulled from memory — no dead links or
defunct organizations. A few notes on how to read this:

- **"Free"** means free to browse/read. A couple (Cochrane) have a mixed
  model, noted where relevant.
- Sources already wired into the app (Wikipedia, Wikiquote, Semantic
  Scholar, Wikipedia On This Day) aren't re-listed under every topic — see
  the note at the end for which of these would need real integration work
  vs. which are just good manual references.
- Where a specialty body has an official coaching/education arm (ITF, USTA,
  Goethe-Institut), that's listed over the org's generic homepage.

## Practical Philosophy
1. **Stanford Encyclopedia of Philosophy** — plato.stanford.edu — peer-reviewed, rigorous, entirely free
2. **Internet Encyclopedia of Philosophy** — iep.utm.edu — peer-reviewed, more accessible tone
3. **PhilPapers** — philpapers.org — free index/search of philosophy papers and preprints
4. **Perseus Digital Library** — perseus.tufts.edu — primary Greek/Roman philosophical texts, original + translation
5. **Project Gutenberg** — gutenberg.org — full public-domain philosophy texts
6. **Modern Stoicism / Stoicism Today** — modernstoicism.com — UK nonprofit; free Stoic Week course + blog run by academics and therapists
7. **Google Scholar** — scholar.google.com — free search across scholarly philosophy literature

## On actually wiring these into the app

Not all of these are equally easy to pull into Curio's live-fetch model:

- **Easy, same pattern as Wikipedia/Wikiquote**: Chinese Text Project and
  most Fordham Sourcebooks pages are plain HTML with parseable structure —
  similar effort to what `sources.js` already does for Wikiquote.
- **Needs a different approach**: government sites (Investor.gov, CFPB,
  Goethe-Institut, National Institute of Korean Language) generally don't
  expose search/summary APIs the way MediaWiki does — pulling live "cards"
  from them would mean scraping specific known pages rather than searching,
  which is more fragile and worth hardcoding a curated set (like the
  existing German/Korean vocab in `curated.js`) rather than fetching live.
- **PubMed/PMC**: NCBI does have a public E-utilities API
  (`eutils.ncbi.nlm.nih.gov`) that could plug in alongside Semantic Scholar
  for the research-heavy topics — I haven't tested it end-to-end for
  browser CORS behavior, so treat that as worth a spike before relying on it.
- **Cochrane Library**: plain-language summaries are free; full reviews are
  free in 100+ countries via national provisions but not universally — not
  a great fit for a "just fetch it" source without knowing the reader's
  location.

Happy to build out any of these into `sources.js` the same way Wikiquote
was done, if you want to expand past the current Wikipedia-centric set.
